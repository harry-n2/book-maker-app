## 0. 核心結論（一言で）

**マンガは「AIに毎回自由に描かせる」のではなく、「固定フォーマットに原稿を流し込む変換工程」にする。** これが唯一、再現性（同じ入力で同じ品質）と出版物としての成立を両立する。
AIに自由裁量を残すほど品質が揺れる。よって構成・ページ数・コマ割り・キャラ設定は**テンプレ＋JSON契約で固定**し、AIは「中身の文章」と「コマ内の絵」だけ担当させる。

担当分離：
- **Gemini** = ストーリー・構成・ネーム（各コマの内容）
- **アプリ側** = テンプレ選択・コマ枠座標・読み順・余白・写植
- **画像AI(Image 2)** = コマ内の「絵」だけ
- **後処理** = 吹き出し・縦書き写植・合成・EPUB/PDF化

## 1. ご指摘6点への具体設計

### ① 構成（ストーリー構造）
- **固定テンプレに割り当てる方式**（AIに構成を発明させない）。MVPは `24p起承転結v1`（起5/承8/転7/結4）等を版固定。
- 温度 `0〜0.2`。`theme/protagonist/want/need/conflict/ending/emotional_arc` 以外を増やさせない。
- 出力は構成JSON（`schema_version`付き）。JSON Schemaで「ページ数違い・読み順違い・セリフの画像混入」を機械的に弾く。

### ② ネーム（コマ単位の脚本）
- コマ＝出版用設計図としてJSON化。各コマに必須フィールド：
  `panel_id / reading_order / layout_slot / panel_role / scene / characters[{id,pose,expression,gaze,costume_state}] / composition{shot,angle,focus,background} / dialogue[{speaker,text,balloon_id,placement}] / sfx / image_instruction{must_include, must_not_include, no_text_in_image:true}`。
- 生成後に7検査（構造/読み順/写植/演出=1コマ1動作/連続性/出版成立性/IP）。
- セリフは1吹き出し**8〜22字**目安、1コマ最大2吹き出し。

### ③ ページ数
- **文字数でなく「物語ビート数」から決める**。`仮ページ数 = ceil(ビート数 / 4)` → 固定バケットに丸める。
- 規定値：MVP=**16〜24ページ**、平均**4コマ/ページ**（3〜5、最大6、1コマは決めゴマのみ）。
- **本文12p未満=出版不可**、**64p超=自動分冊**。会話ビート50%超は場面転換を挿入。

### ④ コマ割り（レイアウト）
- **検証済みテンプレID方式**（自由bbox生成は破綻するため禁止）。まず20〜40種（1〜6コマ用・会話/アクション/見開き/引き）。
- bboxは**正規化整数 `0..10000`**（原点左上）。`reading_order` を明示保存（座標推定に頼らない）。
- 読み順は**右上→左上→右下→左下**固定。検査NG時はAIに直させず**安全テンプレにフォールバック**。
- 斜めコマ・コマ内コマ・端まで食い込む構成は禁止。

### ⑤ キャラ設定の固定（character bible）
- **作品内キャラの唯一の正本JSON**として保存（自然文メモ禁止）。
  `character_id / version / face / hair / body / default_outfit / allowed_outfit_variants / do_not_change[] / negative_prompt[] / reference_assets{三面図,表情表} / prompt_fragment`。
- 初回に**三面図＋表情表**を生成→ユーザー承認→**version をロック**（以後変更不可、変えるなら新version）。
- 全コマに `character_id + bible_version + bible_hash` と最終プロンプト全文を保存。
- 入力は初心者向けに**フォーム化**（年齢/体型/髪色/髪型/目/服装/固定アクセサリ/絶対変えない特徴/禁止要素）。

### ⑥ キャラ画像の一貫性（最重要リスク）
- 手法：**キャラシート先行生成 → 各コマは参照画像つき画像編集で生成 → Visionで一貫性採点 → 失敗理由別に自動リテイク → 後処理合成**。
- 各コマ画像プロンプトはアプリが固定順で組立て、Geminiが曖昧でも `prompt_fragment` と `do_not_change` を**優先注入**。
- **⚠️ 正直な限界（Codex指摘・要承認）**：`gpt-image`系は **seedによる完全再現パラメータが確認できず**、横顔・俯瞰・強い表情・複数人で顔/画風が揺れる。**「同一」保証は不可、「同水準＋検品付き」が現実解**。
  - 厳密な同一キャラ保証が必要なら、将来 **Stable Diffusion + LoRA/ControlNet/IP-Adapter** 併用が代替案（決定事項=OpenAI画像のため、まずは参照画像＋Vision QA＋リテイクで運用し、不足ならこの代替を再検討）。
- 1コマ**1〜2人**を基本（多人数は崩れる）。主要キャラ初登場・決めゴマ・表紙は複数候補生成＋人確認。

## 2. 吹き出し・写植（画像に焼かない）
- 画像生成は**文字なし・吹き出しなし・余白確保**。セリフ/SFX/吹き出しは**後処理でSVG/Canvasベクター合成**。
- 縦書き・禁則・句読点・縦中横を組版ルールで処理。**商用可フォント固定**（源暎アンチック/Noto Serif JP等・ライセンス確認済セット）。
- はみ出し対策：自動改行→吹き出し拡大→分割→短縮。最小サイズ未満はNGで再処理。
- 同じ入力なら**同じ座標・同じ改行・同じフォント**で再現可能。

## 3. 品質ゲートと人手介入
- 検査：キャラ一貫性（identity_confidence<0.85で再生成）/ 読み順 / コマ崩れ（OpenCV+bbox照合）/ 吹き出しはみ出し / 手指・顔崩れ（severity:high再生成）/ 画像内文字（OCRで検出して弾く）/ IP・禁止語。
- リテイクは**失敗理由別に分岐**（ランダム再生成しない）。上限：軽微2回・重要コマ3〜5回→超過は人手キュー。
- **人手は3ゲートだけ**：①キャラシート承認 ②冒頭数ページのトーン確認 ③出版前プレビュー。

---

## 4. 再現性の心臓 = `MangaManifest v1`
原稿→構成→ネーム→キャラ参照→コマ画像→写植→EPUB/PDF の全ステップを**1つの再実行可能なJSON契約**に固定。各成果物に保存：
`input_hash / prompt_version / model_name+version / params / character bible_hash / layout_template_id / フォント版 / 各コマ期待値 / output_hash / approval_state`。
**同一入力は再生成せず保存済み成果物を返す**（冪等キャッシュ）。

## 5. MVPパイプライン（成立する最小形）
入力（ジャンル/読者年齢/テーマ/主人公/トーン）→ Manifest生成 → ネーム確定（固定4コマテンプレ）→ キャラシート生成・承認ロック → コマ画像生成（参照画像）→ 自動QA（OCR/類似度/読み順/余白/IP）→ 写植・組版（縦書き）→ 固定レイアウトEPUB＋確認PDF。
インフラ：Vercel(UI/API)＋QStash(工程別非同期)＋Postgres(Manifest/状態/hash)＋Blob(画像/PDF/EPUB)。

## 6. コスト目安（要・一次確認）
16p×4コマ=64画像＋表紙＋キャラシート＋リテイク≒**約75画像/冊**。Codex web参照では画像はトークン課金（"GPT-Image-2 $30/1M tokens"表記あり）→ **1冊 画像$3〜8＋文章$0.1〜1** 目安。
> ⚠️ `gpt-image`の**正式モデルID（Image 2 / gpt-image-1）・サイズ・seed有無・単価・組織確認要否**、QStash/Blob/Vercel/Neon の料金は**実装着手時に各公式docで一次確認**してから確定（現値は二次情報）。KDPは**AI生成コンテンツ申告**が必要→申告サマリーを自動生成。

## 7. 初心者UX
画面は「入力→生成中→プレビュー→修正→出版DL」の5段だけ。選ぶのは「短編/標準・絵柄3種・対象年齢・明るい/シリアス」程度。エラーは行動可能文言（例「このキャラが安定しません。設定を簡単にしました」）。
